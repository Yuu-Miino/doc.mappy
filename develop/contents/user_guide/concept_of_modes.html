Concept of modes#

Many systems of practical interest are piecewise smooth: an ODE whose right-hand side switches between regions, an ODE with impacts or resets, a periodically forced system observed once per period. Their Poincaré maps are not given by a single smooth formula, which makes Jacobians — and therefore Newton’s method, stability analysis and bifurcation analysis — awkward to obtain.

The mode concept (Miino, NOLTA 2024) splits such a system into primitive smooth pieces, the modes, and represents the Poincaré map as a composition of the maps they induce,

\[T = T_{m-1} \circ T_{m-2} \circ \cdots \circ T_1 \circ T_0, \qquad T_i : M_i \to M_{i+1},\]

where every \(T_i\) is a smooth diffeomorphism between (possibly different-dimensional) spaces \(M_i\). Derivatives of \(T\) then follow from the derivatives of the \(T_i\) by the chain rule (see Jacobian and Hessian tensor).

Modes#

A mode is a named, smooth step from an initial state to a final state. Both kinds of modes implement Mode.step, which returns a StepResult with the final state y and, on request, the Jacobian jac and Hessian hes of the mode map.

Continuous modes#

A ContinuousMode integrates an autonomous ODE

\[\deriv{\bm x}{t} = \bm f(\bm x, p), \qquad \bm x \in \R^n,\]

declared with vector_field(), from \(\bm x_0\) until the trajectory \(\bm\varphi(t, \bm x_0)\) reaches one of its borders. The mode map is

\[T_i(\bm x_0) = \bm\varphi(\tau(\bm x_0), \bm x_0),\]

where \(\tau(\bm x_0)\) is the hitting time. The integration uses scipy.integrate.solve_ivp() (method, rtol, atol and other options are forwarded). The integration time is bounded by max_interval (default 20.0): if no border is reached by then, ModeNotTerminatedError is raised. A continuous mode without borders is the time-max_interval flow map.

Non-autonomous systems are made autonomous by adding time as a state variable, \(\dot t = 1\), with a border \(t - T_{\mathrm{period}} = 0\) and a discrete mode that resets \(t\) afterwards. Use SymPy functions for the forcing (sympy.cos(t)) — see Jacobian and Hessian tensor.

Discrete modes#

A DiscreteMode applies a map \(\bm x \mapsto \bm g(\bm x, p)\) once. Maps are declared with mapping(dom_dim, cod_dim) (mapping()); the dimensions may differ, which is how a state is projected onto a lower-dimensional Poincaré section and embedded back. Typical discrete modes are

  • state jumps and resets (impact laws, firing resets, t ← t - T);

  • projections onto the section coordinates (\(\R^n \to \R^{n-1}\)) and their inverses (\(\R^{n-1} \to \R^n\));

  • the map itself, for a system that is discrete from the start (see Diffeomorphism).

Trajectory recording#

Each mode has an in_trajectory flag: continuous modes contribute a sampled TrajectorySegment by default (sampling interval trajectory_dt), discrete modes do not, unless in_trajectory=True, in which case they contribute a two-point segment (only when the domain and codomain dimensions agree).

Borders#

A border is a scalar function \(q(\bm x, p)\) declared with border(); the continuous mode stops where \(q = 0\). The direction argument selects which zero crossings count:

direction

Terminates the mode when \(q\) …

1 (default)

crosses zero from negative to positive;

-1

crosses zero from positive to negative;

0

crosses zero in either direction.

A continuous mode may have several borders, borders=[q0, q1, ...]; the first one reached terminates the mode and its index is reported as StepResult.border. That index selects the next mode (below).

Caution

A trajectory that starts exactly on a border, moving in the border’s direction, terminates immediately with \(\tau = 0\). Make sure that a continuous mode starts off its borders — usually the preceding discrete mode (a reset or a jump) takes care of that.

The derivatives of a continuous mode map include a correction for the dependence of \(\tau\) on \(\bm x_0\). It requires the flow to be transversal to the border, \(\nabla q \cdot \bm f \neq 0\): an exactly tangential hit raises ZeroDivisionError, and a nearly tangential (grazing) hit makes the derivatives ill-conditioned.

Transitions#

The transitions of a PoincareMap (type Transitions) map each mode name to its successor(s):

  • a string — the next mode, regardless of how the mode ended. This is the form for discrete modes, for continuous modes without borders and, as a shorthand, for continuous modes with a single border;

  • a list — one next mode per border, in the order of the borders of a continuous mode: {"flow": ["after_q0", "after_q1"]};

  • a mapping from border name to next mode — {"flow": {"q0": "after_q0", "q1": "after_q1"}}. The name of a border is its function name unless @border(..., name="q0") says otherwise. This form does not depend on the order of borders and is the recommended one for modes with several borders.

The rules are checked when the map is constructed, not when a transition is taken: unknown mode names raise UnknownModeError, and TransitionError reports a rule with the wrong number of entries, an unknown or missing border name, a mode that is reachable from initial_mode but has no rule, a successor whose domain dimension differs from the codomain of the mode, or a graph in which no end mode can be reached. Modes that cannot be reached from initial_mode need no rule.

Initial and end modes#

One iteration of a PoincareMap starts in initial_mode — the mode whose domain is the Poincaré section — and follows the transitions until it enters one of the end_modes (by default just initial_mode). The image is the state entering that end mode, so for the default the map is a self-map of the section.

Several end modes describe a section made of several pieces, e.g. one per region of a switched system. MapResult.end_mode tells which piece the image is on, and image_detail(..., mode=name) starts an iteration from a mode other than initial_mode. When n > 1 iterations are requested, each iteration starts from the end mode reached by the previous one.

max_transitions (default 1000) bounds the number of mode transitions per iteration and guards against transition loops that never reach an end mode.

The mode graph#

Modes and transitions form a directed graph. The Poincaré map is a closed walk in it from the initial mode back to an end mode; non-smooth features of the system appear as branches of the graph, one per border of a continuous mode.

Mode history#

MapResult.mode_history lists the names of the modes visited, starting with the initial mode and ending with the end mode reached; consecutive iterations are concatenated. For the Izhikevich map:

>>> pmap.image_detail(-3.0, params).mode_history
['Pinv', 'B', 'A', 'P', 'Pinv']
>>> pmap.image_detail(-3.0, params, n=2).mode_history
['Pinv', 'B', 'A', 'P', 'Pinv', 'B', 'A', 'P', 'Pinv']

The history identifies which branch of a non-smooth system an orbit took — for example how many switchings occurred within one forcing period. Since the map is smooth only as long as the sequence of modes does not change, a periodic point and its derivatives are always associated with a particular mode history. A change of the history under parameter variation signals a border-collision (grazing) event, which is not a local bifurcation in the sense of find_local_bf().

Discrete-time systems#

A system that is a map from the start needs no section: wrap the map in a Diffeomorphism, which is a one-mode Poincaré map whose mode is called "map":

>>> from mappy_ds import Diffeomorphism, mapping
>>> @mapping(2)
... def henon(y, p):
...     x, u = y
...     return np.array([1 - p["a"] * x**2 + u, p["b"] * x])
>>> henon_map = Diffeomorphism(henon)
>>> henon_map.image([0.0, 0.0], {"a": 1.4, "b": 0.3}, n=2)
array([-0.4,  0.3])

Every Map — PoincareMap or Diffeomorphism — offers image, image_detail and trajectory and can be passed to everything in mappy_ds.root and mappy_ds.plot.
