API reference

MappyDS.MappyDS — Module
MappyDS

Poincaré maps, periodic points and bifurcations of hybrid (smooth / non-smooth) dynamical systems: the Julia counterpart of the Python package mappy-ds.

MappyDS implements the mode concept (Miino, NOLTA, IEICE 15(2), 2024): a dynamical system is split into smooth primitive pieces, modes, connected by transition rules. From the modes the package builds the Poincaré map of the system as a composite diffeomorphism together with its Jacobian matrix and Hessian tensor, which in turn feed periodic-point search, local bifurcation analysis and parameter continuation.

Example

The Izhikevich neuron model with a firing threshold at v = 30:

using MappyDS, StaticArrays

izhikevich = VectorField(2) do y, p
    v, u = y
    return SVector(0.04 * v^2 + 5 * v + 140 - u + p.I, p.a * (p.b * v - u))
end
fire = Border((y, p) -> y[1] - 30, 2)
firing = Mapping((y, p) -> y + SVector(p.c - 30, p.d), 2)
reduce = Mapping((y, p) -> y[2], 2, 1)
revert = Mapping((u, p) -> SVector(30.0, u[1]), 1, 2)

pmap = PoincareMap(
    [
        ContinuousMode(:A, izhikevich; borders = (fire,)),
        DiscreteMode(:B, firing),
        DiscreteMode(:P, reduce),
        DiscreteMode(:Pinv, revert),
    ],
    Dict(:A => [:P], :B => :A, :P => :Pinv, :Pinv => :B),
    :Pinv,
)
params = (a = 0.2, b = 0.2, c = -50.0, d = 2.0, I = 10.0)
res = image_detail(pmap, -3.0, params; hessian = true)
res.y, res.jac, res.hes   # ≈ [-3.47838], [0.27080;;], [-0.19326;;;]
res.mode_history          # [:Pinv, :B, :A, :P, :Pinv]

The implementation plan and the API mapping from the Python package are in docs/JULIA_RELEASE_PLAN.md of the mappy repository.

System functions

MappyDS.Border — Type
Border(q, dim; direction = 1, name = nameof(q))

Declare a border (section) $q(y, p) = 0$ of a continuous mode on $\mathbb{R}^{dim}$ (Python: @border(dim, direction, name)). direction is the zero crossing that terminates the mode: 1 for negative to positive, -1 for positive to negative and 0 for both. name identifies the border in transition rules written as Dict(:mode => Dict(:border => :next)).

source
MappyDS.Mapping — Type
Mapping(f, dom_dim, cod_dim = dom_dim; name = nameof(f))

Declare a discrete map $y \mapsto f(y, p)$ from $\mathbb{R}^{dom\_dim}$ to $\mathbb{R}^{cod\_dim}$ (Python: @mapping(dom_dim, cod_dim)).

Examples

henon = Mapping(2) do y, p
    x, u = y
    return SVector(1 - p.a * x^2 + u, p.b * x)
end
henon([0.0, 0.0], (a = 1.4, b = 0.3))  # [1.0, 0.0]

MappyDS.SystemFunction — Type
SystemFunction

Abstract supertype of VectorField, Mapping and Border: a user function f(y, p) of a state vector y and parameters p together with the dimensions of its domain and codomain.

The function is evaluated on SVectors (StaticArrays) and differentiated with ForwardDiff, so it must be written generically: build the result with SVector(...), [...] or a tuple, do not fix element types to Float64, and read parameters as p.a (a NamedTuple) or any other container you pass. Branches on the values of y are allowed (unlike the SymPy tracing of the Python package), but the function must be differentiable where it is evaluated.

See also jacobian, hessian, dom_dim, cod_dim.

source
MappyDS.VectorField — Type
VectorField(f, dim; name = nameof(f))

Declare the right-hand side of an autonomous ODE $\dot y = f(y, p)$ on $\mathbb{R}^{dim}$ (Python: @vector_field(dim)).

Examples

izhikevich = VectorField(2) do y, p
    v, u = y
    return SVector(0.04 * v^2 + 5 * v + 140 - u + p.I, p.a * (p.b * v - u))
end
jacobian(izhikevich, [0.0, 0.0], (a = 0.2, b = 0.2, I = 10.0))

Modes

MappyDS.ContinuousMode — Type
ContinuousMode(name, fun::VectorField; borders = (), max_interval = 20.0,
               in_trajectory = true, trajectory_dt = 1.0e-2,
               alg = Tsit5(), reltol = 1.0e-6, abstol = 1.0e-9, solver_kwargs...)

A mode whose evolution follows the autonomous ODE fun until one of the borders (Borders of the same dimension, with distinct names) is crossed in the direction it declares. Without borders the mode is the time-max_interval flow map. alg is any OrdinaryDiffEq algorithm (the default Tsit5() corresponds to SciPy's RK45); reltol, abstol and the remaining keyword arguments are forwarded to solve.

When derivatives are requested the first and second variational equations are integrated together with the state and the result is corrected for the dependence of the hitting time on the initial state (Miino, NOLTA, IEICE 15(2), 2024). The image then differs from the one obtained without derivatives by an amount of the order of the solver tolerance, because the adaptive step sizes change.

source
MappyDS.DiscreteMode — Type
DiscreteMode(name, fun::Mapping; in_trajectory = false)

A mode whose evolution is a single application of the map fun. in_trajectory decides whether the jump contributes a two-point TrajectorySegment to recorded trajectories.

source
MappyDS.Mode — Type
Mode

Abstract supertype of ContinuousMode and DiscreteMode: a primitive, smooth piece of a hybrid system together with the rule that terminates it. Both kinds expose evolve.

source
MappyDS.StepResult — Type
StepResult

Result of evolve. Fields: y (state at the end of the mode), jac (jac[i, j] = ∂y_i/∂y0_j), hes (hes[i, j, k] = ∂²y_i/(∂y0_j ∂y0_k)), jac_p and hes_p (parameter derivatives, from MappyDS 0.2 / 0.3), border (1-based index of the border that terminated a continuous mode, nothing otherwise), t (time spent in a continuous mode) and segment (the recorded TrajectorySegment). Derivatives that were not requested are nothing.

MappyDS.evolve — Function
evolve(mode, y0, p = nothing; jacobian = false, hessian = false, trajectory = false) -> StepResult

Evolve the state y0 through the mode (Python: Mode.step). jacobian and hessian request the Jacobian matrix and the Hessian tensor of the mode map (hessian implies jacobian); trajectory records the trajectory within the mode if the mode is in_trajectory.

AbstractMap

Abstract supertype of maps built from modes (PoincareMap and Diffeomorphism). Subtypes implement image_detail; image and trajectory are convenience wrappers.

MappyDS.Diffeomorphism — Type
Diffeomorphism(fun::Mapping; name = :map)

A discrete map $y \mapsto f(y, p)$ on $\mathbb{R}^n$ as a map with a single mode named name; fun must have equal domain and codomain dimensions. The underlying Mapping is d.fun.

source
MappyDS.MapResult — Type
MapResult

Image of a point under a map with derivatives (Python: MapResult). Fields: y, jac (jac[i, j] = ∂y_i/∂y0_j), hes (hes[i, j, k] = ∂²y_i/(∂y0_j ∂y0_k)), jac_p, hes_p (parameter derivatives, from MappyDS 0.2 / 0.3), param_keys (keys of the parameter NamedTuple), mode_history (names of the modes visited, from the initial to the final one) and trajectory. Derivatives that were not requested are nothing.

The characteristic multipliers are available through LinearAlgebra.eigvals(res) and the eigenvectors through LinearAlgebra.eigvecs(res); see also end_mode.

source
MappyDS.PoincareMap — Type
PoincareMap(modes, transitions, initial_mode, end_modes = nothing; max_transitions = 1000)

Poincaré map of a hybrid system described by modes and transition rules.

Starting in initial_mode, the state is evolved mode by mode following transitions until one of the end_modes (by default initial_mode) is reached; that is one iteration of the map. The Jacobian and Hessian are composed with the chain rule along the way.

transitions maps each mode name (a Symbol) to its successor:

  • a mode name for a discrete mode, a borderless continuous mode or, as a shorthand, a continuous mode with a single border;
  • a vector or tuple of mode names, one per border in the order of borders;
  • a Dict(:border_name => :mode_name) covering every border of the mode.

Only modes reachable from initial_mode need a rule. The map is validated at construction: unknown names raise UnknownModeError; rules that do not fit their mode, missing rules for reachable modes, dimension mismatches between a mode and its successor and unreachable end modes raise TransitionError. max_transitions bounds the number of mode transitions per iteration.

MappyDS.image_detail — Function
image_detail(map, y0, p = nothing; n = 1, jacobian = true, hessian = false,
             trajectory = false, mode = nothing) -> MapResult

Compute the n-th image of y0 under the map with derivatives. jacobian (default true) and hessian request the Jacobian matrix and the Hessian tensor; trajectory records the trajectory. For a PoincareMap, mode starts the iteration in another mode than initial_mode (useful when a previous image ended in a different end mode).

Requesting derivatives integrates the variational equations together with the state, which changes the adaptive step sizes of the ODE solver; the image therefore differs slightly (on the order of the solver tolerance) from the one obtained with jacobian = false.

Trajectories

MappyDS.Trajectory — Type
Trajectory(segments = TrajectorySegment[])

A trajectory as a sequence of TrajectorySegments in chronological order. Modes with in_trajectory = false do not contribute a segment.

traj.y concatenates the states of all segments (dim × n_points); it throws an ArgumentError if the segments have different dimensions.

source
MappyDS.TrajectorySegment — Type
TrajectorySegment(mode, kind, y, t = nothing)

The part of a trajectory spent in a single mode. kind is :continuous or :discrete, y holds the sampled states as columns (dim × n_points; a discrete segment holds the two points before and after the map) and t the sampling times relative to the start of the segment (nothing for discrete segments).

Periodic points and continuation

MappyDS.CycleResult — Type
CycleResult

Result of find_cycle. Fields: success, retcode (SciMLBase.ReturnCode of the nonlinear solver), y (the periodic point, nothing on failure), eigvals and eigvecs (characteristic multipliers and eigenvectors of the Jacobian of the period-th iterate at y, nothing on failure), nfev (number of evaluations of the map) and residual (Tⁿ(y) - y at the last iterate).

source
MappyDS.find_cycle — Function
find_cycle(map, y0, p = nothing; period = 1, alg = SimpleTrustRegion(),
           abstol = 1.0e-10, reltol = 1.0e-10, maxiters = 100, kwargs...) -> CycleResult

Find a periodic point of a map by solving $T^n(y) - y = 0$ with the analytic Jacobian $DT^n(y) - I$ provided by the map, where $T$ is map and $n$ is period. The system is a SciMLBase.NonlinearProblem; alg is any algorithm of SimpleNonlinearSolve or NonlinearSolve, and the remaining keyword arguments are forwarded to solve.

Examples

henon = Mapping(2) do y, p
    x, u = y
    return SVector(1 - p.a * x^2 + u, p.b * x)
end
res = find_cycle(Diffeomorphism(henon), [0.6, 0.2], (a = 1.4, b = 0.3))
res.y        # ≈ [0.631354, 0.189406]
res.eigvals  # ≈ [-1.923739, 0.155946]

MappyDS.trace_cycle — Method
trace_cycle(map, y0, params::NamedTuple, param_key::Symbol, end_value;
            period = 1, resolution = 100, show_progress = false, callback = nothing,
            kwargs...) -> Vector{ContinuationStep}

Continue a periodic point along a parameter: calls find_cycle at each point of a continuation of params[param_key] from its current value to end_value, starting each search from the previous periodic point. The info of each step holds :eigvals, :eigvecs, :nfev and :residual as in CycleResult. The remaining keyword arguments are forwarded to find_cycle.

MappyDS.StepFunctionResult — Type
StepFunctionResult(success, y = nothing, params = nothing, info = nothing)

Return value of a step function passed to continuation. The continuation stops at the first step with success == false or y === nothing. params replaces the parameters for the following steps (e.g. with a solved parameter updated); info is stored in ContinuationStep.

source
MappyDS.continuation — Method
continuation(fun, y0, params::NamedTuple, param_key::Symbol, end_value;
             resolution = 100, show_progress = false, callback = nothing)

Continue the solution of a step function along a parameter.

params[param_key] is swept linearly from its current value to end_value in resolution points, both ends included. At each point fun(y, p) is called, where y and p are those of the previous successful step (y0 and params at the first point) with p[param_key] set to the current value; it must return a StepFunctionResult. The sweep stops at the first unsuccessful step. callback is called with each successful ContinuationStep; show_progress prints one status line per step to stderr.

Examples

step(y, p) = StepFunctionResult(true, sqrt(p.p))
steps = continuation(step, 1.0, (p = 1.0,), :p, 4.0; resolution = 4)
[(s.params.p, s.y) for s in steps]  # (1.0, 1.0), (2.0, 1.414…), (3.0, 1.732…), (4.0, 2.0)
