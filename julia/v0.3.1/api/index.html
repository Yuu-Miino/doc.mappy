API reference

MappyDS.MappyDS — Module
MappyDS

Poincaré maps, periodic points and bifurcations of hybrid (smooth / non-smooth) dynamical systems: the Julia counterpart of the Python package mappy-ds.

MappyDS implements the mode concept (Miino, NOLTA, IEICE 15(2), 2024): a dynamical system is split into smooth primitive pieces, modes, connected by transition rules. From the modes the package builds the Poincaré map of the system as a composite diffeomorphism together with its Jacobian matrix and Hessian tensor, which in turn feed periodic-point search, local bifurcation analysis and parameter continuation.

Example

The Izhikevich neuron model with a firing threshold at v = 30:

using MappyDS, StaticArrays

izhikevich = VectorField(2) do y, p
    v, u = y
    return SVector(0.04 * v^2 + 5 * v + 140 - u + p.I, p.a * (p.b * v - u))
end
fire = Border((y, p) -> y[1] - 30, 2)
firing = Mapping((y, p) -> y + SVector(p.c - 30, p.d), 2)
reduce = Mapping((y, p) -> y[2], 2, 1)
revert = Mapping((u, p) -> SVector(30.0, u[1]), 1, 2)

pmap = PoincareMap(
    [
        ContinuousMode(:A, izhikevich; borders = (fire,)),
        DiscreteMode(:B, firing),
        DiscreteMode(:P, reduce),
        DiscreteMode(:Pinv, revert),
    ],
    Dict(:A => [:P], :B => :A, :P => :Pinv, :Pinv => :B),
    :Pinv,
)
params = (a = 0.2, b = 0.2, c = -50.0, d = 2.0, I = 10.0)
res = image_detail(pmap, -3.0, params; hessian = true)
res.y, res.jac, res.hes   # ≈ [-3.47838], [0.27080;;], [-0.19326;;;]
res.mode_history          # [:Pinv, :B, :A, :P, :Pinv]

The implementation plan and the API mapping from the Python package are in docs/JULIA_RELEASE_PLAN.md of the mappy repository.

MappyDS.SystemFunction — Type
SystemFunction

Abstract supertype of VectorField, Mapping and Border: a user function f(y, p) of a state vector y and parameters p together with the dimensions of its domain and codomain.

The function is evaluated on SVectors (StaticArrays) and differentiated with ForwardDiff, so it must be written generically: build the result with SVector(...), [...] or a tuple, do not fix element types to Float64, and read parameters as p.a (a NamedTuple) or any other container you pass. Branches on the values of y are allowed (unlike the SymPy tracing of the Python package), but the function must be differentiable where it is evaluated.

See also jacobian, hessian, dom_dim, cod_dim.

Modes

MappyDS.ContinuousMode — Type
ContinuousMode(name, fun::VectorField; borders = (), max_interval = 20.0,
               in_trajectory = true, trajectory_dt = 1.0e-2,
               alg = Tsit5(), reltol = 1.0e-6, abstol = 1.0e-9, solver_kwargs...)

A mode whose evolution follows the autonomous ODE fun until one of the borders (Borders of the same dimension, with distinct names) is crossed in the direction it declares. Without borders the mode is the time-max_interval flow map. alg is any OrdinaryDiffEq algorithm (the default Tsit5() corresponds to SciPy's RK45); reltol, abstol and the remaining keyword arguments are forwarded to solve.

When derivatives are requested the first and second variational equations are integrated together with the state and the result is corrected for the dependence of the hitting time on the initial state (Miino, NOLTA, IEICE 15(2), 2024). The image then differs from the one obtained without derivatives by an amount of the order of the solver tolerance, because the adaptive step sizes change.

source

A mode whose evolution is a single application of the map fun. in_trajectory decides whether the jump contributes a two-point TrajectorySegment to recorded trajectories.

evolve(mode, y0, p = nothing; jacobian = false, hessian = false,

MappyDS.MapResult — Type
MapResult

Image of a point under a map with derivatives (Python: MapResult). Fields: y, jac (jac[i, j] = ∂y_i/∂y0_j), hes (hes[i, j, k] = ∂²y_i/(∂y0_j ∂y0_k)), jac_p, hes_p (parameter derivatives, from MappyDS 0.2 / 0.3), param_keys (keys of the parameter NamedTuple), mode_history (names of the modes visited, from the initial to the final one) and trajectory. source
MappyDS.PoincareMap — Type
PoincareMap(modes, transitions, initial_mode, end_modes = nothing; max_transitions = 1000)

Poincaré map of a hybrid system described by modes and transition rules.

Starting in initial_mode, the state is evolved mode by mode following transitions until one of the end_modes (by default initial_mode) is reached; that is one iteration of the map. The Jacobian and Hessian are composed with the chain rule along the way.

transitions maps each mode name (a Symbol) to its successor:

  • a mode name for a discrete mode, a borderless continuous mode or, as a shorthand, a continuous mode with a single border;
  • a vector or tuple of mode names, one per border in the order of borders;
  • a Dict(:border_name => :mode_name) covering every border of the mode.

Only modes reachable from initial_mode need a rule. The map is validated at construction: unknown names raise UnknownModeError; rules that do not fit their mode, missing rules for reachable modes, dimension mismatches between a mode and its successor and unreachable end modes raise TransitionError. max_transitions bounds the number of mode transitions per iteration.

MappyDS.image_detail — Function
image_detail(map, y0, p = nothing; n = 1, jacobian = true, hessian = false,
             parameter_jacobian = false, parameter_hessian = false,
             trajectory = false, mode = nothing) -> MapResult

Compute the n-th image of y0 under the map with derivatives. jacobian (default true) and hessian request the Jacobian matrix and the Hessian tensor; parameter_jacobian requests the derivative with respect to every parameter of the NamedTuple p (MapResult.jac_p, columns in the order of MapResult.param_keys; implies jacobian); parameter_hessian requests the mixed second derivative MapResult.hes_p (implies hessian and parameter_jacobian); trajectory records the trajectory. For a PoincareMap, mode starts the iteration in another mode than initial_mode (useful when a previous image ended in a different end mode).

Requesting derivatives integrates the variational equations together with the state, which changes the adaptive step sizes of the ODE solver; the image therefore differs slightly (on the order of the solver tolerance) from the one obtained with jacobian = false.

MappyDS.find_cycle — Function
find_cycle(map, y0, p = nothing; period = 1, alg = SimpleTrustRegion(),
           abstol = 1.0e-10, reltol = 1.0e-10, maxiters = 100, kwargs...) -> CycleResult

Find a periodic point of a map by solving $T^n(y) - y = 0$ with the analytic Jacobian $DT^n(y) - I$ provided by the map, where $T$ is map and $n$ is period. The system is a SciMLBase.NonlinearProblem; alg is any algorithm of SimpleNonlinearSolve or NonlinearSolve, and the remaining keyword arguments are forwarded to solve.

Examples

henon = Mapping(2) do y, p
    x, u = y
    return SVector(1 - p.a * x^2 + u, p.b * x)
end
res = find_cycle(Diffeomorphism(henon), [0.6, 0.2], (a = 1.4, b = 0.3))
res.y        # ≈ [0.631354, 0.189406]
res.eigvals  # ≈ [-1.923739, 0.155946]

MappyDS.trace_cycle — Method
trace_cycle(map, y0, params::NamedTuple, param_key::Symbol, end_value;
            period = 1, resolution = 100, show_progress = false, callback = nothing,
            kwargs...) -> Vector{ContinuationStep}

Continue a periodic point along a parameter: calls find_cycle at each point of a continuation of params[param_key] from its current value to end_value, starting each search from the previous periodic point. The info of each step holds :eigvals, :eigvecs, :nfev and :residual as in CycleResult. The remaining keyword arguments are forwarded to find_cycle.

source
MappyDS.trace_cycle_arclength — Method
trace_cycle_arclength(map, y0, params::NamedTuple, param_key::Symbol;
                      period = 1, direction = 1, bounds = nothing,
                      step = 0.01, step_min = 1e-6, step_max = 0.1, max_steps = 1000,
                      newton_tol = 1e-10, newton_max_iter = 10,
                      show_progress = false, callback = nothing) -> Vector{ContinuationStep}

Follow a branch of periodic points by pseudo-arclength continuation.

Unlike trace_cycle, which prescribes the parameter values, this continuation treats the periodic point and the parameter together as a point $u = (y, λ)$ on the curve $T^n(y, λ) - y = 0$ and advances along the curve itself, so folds (saddle-node bifurcations), where the branch turns back in $λ$, are passed and the continuation carries on along the other side. The tangent of the curve is the null vector of $[DT^n - I \mid ∂T^n/∂λ]$, available analytically from MapResult.jac and MapResult.jac_p.

Bifurcations along the branch are detected from sign changes between consecutive points and recorded in info[:events] of the later point:

  • :fold: the tangent's parameter component changes sign;
  • :branch_point: $\det(DT^n - I)$ changes sign without a fold (transcritical or pitchfork; the continuation follows one branch);
  • :period_doubling: $\det(DT^n + I)$ changes sign;
  • :neimark_sacker: a complex pair of multipliers crosses the unit circle.

direction (+1: $λ$ increasing first) and bounds ((lo, hi) on $λ$) work as in arclength_continuation, as do step, step_min, step_max, max_steps, newton_tol and newton_max_iter. Each step's info holds :eigvals, :eigvecs, :tangent (unit vector in the $(y, λ)$ space), :step, :newton_iterations and :events.

Examples

The fixed point of y ↦ y + p - y² exists for p ≥ 0 only; both fixed points ±√p lie on one curve that folds at p = 0:

f = Mapping((y, p) -> y[1] + p.p - y[1]^2, 1)
steps = trace_cycle_arclength(Diffeomorphism(f), [0.5], (p = 0.25,), :p;
    direction = -1, step = 0.05, step_max = 0.1, bounds = (-1.0, 0.25))
any(:fold in s.info[:events] for s in steps)         # true
steps[end].y[1] < 0 && steps[end].params.p > 0       # true: the lower branch

MappyDS.LocalBfResult — Type
LocalBfResult

Result of find_local_bf. Fields: success, retcode, y (periodic point at the bifurcation), eigvals, eigvecs, nfev, residual ($T^n(y) - y$ followed by the real and imaginary parts of $\det(DT^n(y) - e^{iθ} I)$ at the last iterate), params (the parameters with the bifurcation parameter at its solved value) and theta (argument of the critical multiplier). y, eigvals, eigvecs, params and theta are nothing on failure.

source
MappyDS.find_local_bf — Method
find_local_bf(map, y0, params::NamedTuple, param_key::Symbol, theta;
              period = 1, alg = SimpleTrustRegion(), abstol = 1e-10, reltol = 1e-10,
              maxiters = 100, kwargs...) -> LocalBfResult

Find a local bifurcation point of a periodic point.

A periodic point $y$ of period $n$ undergoes a local bifurcation when one of its characteristic multipliers crosses the unit circle at $μ = e^{iθ}$. The unknowns $(y, λ, θ)$, with $λ$ = params[param_key], are solved from

\[T^n(y) - y = 0, \qquad \det(DT^n(y) - e^{iθ} I) = 0,\]

the determinant being split into its real and imaginary parts. The initial theta selects the kind of bifurcation: 0 ($μ = 1$) a tangent (saddle-node) bifurcation, pi ($μ = -1$) a period-doubling bifurcation, any other value a Neimark–Sacker bifurcation (a complex pair $e^{±iθ}$ on the unit circle). The Jacobian of the system is supplied analytically from the map's jac, hes, jac_p and hes_p. The nonlinear solver and its options are as in find_cycle.

source
MappyDS.trace_local_bf — Method
trace_local_bf(map, y0, params::NamedTuple, bf_param_key::Symbol, theta,
               cnt_param_key::Symbol, end_value; period = 1, resolution = 100,
               show_progress = false, callback = nothing, kwargs...) -> Vector{ContinuationStep}

Continue a local bifurcation along a second parameter: params[cnt_param_key] is swept from its current value to end_value, and at each point find_local_bf solves for the periodic point, params[bf_param_key] and θ, starting from the previous solution. The result traces a bifurcation curve in the (cnt_param_key, bf_param_key) plane. Each step's y is the periodic point, params holds both parameters and info holds :theta, :eigvals, :eigvecs, :nfev and :residual. The two keys must differ.

MappyDS.trace_local_bf_arclength — Method
trace_local_bf_arclength(map, y0, params::NamedTuple, bf_param_key::Symbol, theta,
                         cnt_param_key::Symbol; period = 1, direction = 1, bounds = nothing,
                         step = 0.01, step_min = 1e-6, step_max = 0.1, max_steps = 1000,
                         newton_tol = 1e-10, newton_max_iter = 10,
                         show_progress = false, callback = nothing) -> Vector{ContinuationStep}

Follow a local-bifurcation curve by pseudo-arclength continuation.

The bifurcation conditions of find_local_bf are $d + 2$ equations in the $d + 3$ unknowns $u = (y, λ_{bf}, θ, λ_{cnt})$, so their solutions form a curve: the bifurcation curve in the $(λ_{cnt}, λ_{bf})$ plane together with the periodic point and the argument of the critical multiplier. The curve is followed with arclength_continuation, so it may turn back in $λ_{cnt}$ (as a fold curve does at a cusp) without stopping. The Jacobian of the system is fully analytic.

Events between consecutive points are recorded in info[:events] of the later point: :fold (the curve turns back in $λ_{cnt}$; for a fold curve this happens at a cusp), :resonance_1_1, :resonance_1_2, :resonance_1_3, :resonance_1_4 (on a Neimark–Sacker curve, $θ$ passes $0$, $π$, $2π/3$ or $π/2$) and :second_multiplier_crossing (the number of multipliers outside the unit circle changes, i.e. another bifurcation curve is crossed). Each step's info also holds :theta, :eigvals, :eigvecs, :tangent (unit vector in the $u$ space), :step and :newton_iterations. direction and bounds refer to $λ_{cnt}$.

Examples

The cusp normal form x ↦ x + l1 + l2 x - x³ has the fold curve l2 = 3x², l1 = -2x³, which turns back in l2 at the cusp (0, 0):

cusp = Mapping((x, p) -> x[1] + p.l1 + p.l2 * x[1] - x[1]^3, 1)
steps = trace_local_bf_arclength(Diffeomorphism(cusp), [0.5], (l1 = -0.25, l2 = 0.75), :l1, 0.0, :l2;
    direction = -1, step = 0.1, step_max = 0.2, bounds = (-1.0, 0.75))
any(:fold in s.info[:events] for s in steps)           # true
steps[end].y[1] < 0 && steps[end].params.l1 > 0        # true: the lower branch

MappyDS.arclength_continuation — Method
arclength_continuation(fun, u0; step = 0.01, step_min = 1e-6, step_max = 0.1,
                       max_steps = 1000, direction = 1, bounds = nothing,
                       newton_tol = 1e-10, newton_max_iter = 10, callback = nothing)

Follow a solution curve of $F(u) = 0$ by pseudo-arclength continuation.

fun(u) returns the residual $F(u)$ (length m) and its Jacobian (m × (m + 1)); $F : \mathbb{R}^{m+1} \to \mathbb{R}^m$ has a one-dimensional zero set. Starting from u0 (first corrected onto the curve with its last component held fixed), each step predicts $u = u_k + h t_k$ along the unit tangent $t_k$ and corrects it with Newton's method on the bordered system $F(u) = 0$, $t_k \cdot (u - u_k) = h$, whose Jacobian $[J; t_k^T]$ is regular even where $J$ loses rank in the parameter direction, so folds are passed without special treatment (Keller, 1977). The step grows by 1.5 when Newton converges in at most three iterations, is halved when six or more are needed or when it fails, and the orientation is kept by requiring $t_k \cdot t_{k+1} > 0$.

The last component of u is the parameter-like coordinate used by direction (+1 to start with it increasing, -1 decreasing) and bounds ((lo, hi): stop when it would leave the interval; the last step is shortened so that the final point lies close to the boundary). fun may throw a MappyError, a SingularException or a DomainError to signal that u is not evaluable; the step is then retried with a smaller h. The continuation stops when bounds are left, max_steps is reached, the step cannot be reduced below step_min, or the curve closes on itself; it throws an ErrorException if u0 cannot be corrected onto the curve.

The arclength is measured in the Euclidean metric of u; if the state and the parameter have very different scales, rescale the parameter in fun. For maps built on ODE solves, the noise floor of the map limits the accuracy the corrector can reach: use solver tolerances well below newton_tol (e.g. reltol = 1e-8, abstol = 1e-10) or raise newton_tol.

Examples

circle(u) = ([dot(u, u) - 1.0], permutedims(2u))
pts = arclength_continuation(circle, [1.0, 0.0]; step = 0.3, step_max = 0.3)
all(abs(dot(p.u, p.u) - 1) < 1e-9 for p in pts)  # true; stops after one turn

MappyDS.continuation — Method
continuation(fun, y0, params::NamedTuple, param_key::Symbol, end_value;
             resolution = 100, show_progress = false, callback = nothing)

Continue the solution of a step function along a parameter.

params[param_key] is swept linearly from its current value to end_value in resolution points, both ends included. At each point fun(y, p) is called, where y and p are those of the previous successful step (y0 and params at the first point) with p[param_key] set to the current value; it must return a StepFunctionResult. The sweep stops at the first unsuccessful step. callback is called with each successful ContinuationStep; show_progress prints one status line per step to stderr.

Examples

step(y, p) = StepFunctionResult(true, sqrt(p.p))
steps = continuation(step, 1.0, (p = 1.0,), :p, 4.0; resolution = 4)
[(s.params.p, s.y) for s in steps]  # (1.0, 1.0), (2.0, 1.414…), (3.0, 1.732…), (4.0, 2.0)

MappyDS.PlotConfig — Type
PlotConfig(; kwargs...)

Configuration of plot2d. Keyword arguments and defaults:

  • only_map = false: draw only the image points, not the trajectories;
  • figsize = (600, 600): figure size in pixels;
  • xlabel = "x", ylabel = "y": axis labels;
  • xlim = (-3.0, 3.0), ylim = (-3.0, 3.0): axis limits;
  • xkey = 1, ykey = 2: indices of the state components on the axes;
  • linewidth = 1.0, markersize = 4.0: trajectory line width and marker size;
  • param_keys = Symbol[], param_index = 1, param_step = 0.1: parameters that can be changed with the up/down keys, the one selected first and the increment of one key press;
  • scalar_axis = :x: for one-dimensional maps, the axis whose coordinate becomes the state when the figure is clicked;
  • trajectory_style, point_style, click_style: a LineStyle, or for the first two a Dict{Symbol, LineStyle} with one style per mode name (the key :_default is used for modes not listed).

MappyDS.plot2d — Method
plot2d(map, y0, p = nothing, config = PlotConfig(); mode = nothing,
       frames = nothing, show = true) -> Figure

Iterate a map and draw its orbit (Python: mappy_ds.plot.plot2d). Requires a Makie backend. Each frame computes one iteration of map from the current state and draws the trajectory segments (unless config.only_map) and the image point.

With frames = n the figure is built non-interactively from n iterations and returned (use it with CairoMakie to save a picture). Otherwise the figure keeps iterating (one iteration per rendered frame, GLMakie) and reacts to the user:

  • mouse click: restart from the clicked coordinates (for a one-dimensional state the coordinate on config.scalar_axis);
  • space or e: clear the axis;
  • f: toggle drawing the trajectories;
  • p: select the next parameter of config.param_keys;
  • up/down: change the selected parameter by config.param_step.

mode starts a PoincareMap in another mode than its initial_mode; later iterations continue from the mode each image ends in. show = false skips display(fig).
